# Phase 7 Implementation Plan — Label printing

> **For agentic workers:** RECOMMENDED SUB-SKILL: `superpowers:executing-plans`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `lot.label_reprint_needed` a trustworthy signal across every label-invalidating mutation; wire the dead `BulkMoveDialog` reprint checkbox; add a bulk-reprint affordance from inventory selection; show a verify-popup at the end of bulk prints (because Browser Print's 200 ≠ "label produced"); run T-G1 on the actual ZP450.

**Architecture:** Continues Phase 1–6 patterns. No new server deps. New client hook (`useBulkLabelPrint`) follows the existing `useLabelPrint` shape (render → POST helper) but with serial loop + aggregated progress toast. Two new dialog components match the existing `Bulk*Dialog` shape. No schema migration — `lot.label_reprint_needed` (col + partial index) already exists from migration `0014`.

### Area D — Bulk-print hook + wire `BulkMoveDialog` checkbox

- [ ] **D.1** Create `src/hooks/useBulkLabelPrint.ts`:
  - Pattern: `useMutation` whose `mutationFn` takes `lotIds: string[]`; reads `helperUrl` from `useSystemSettings`; if missing, throws `NO_HELPER_URL` immediately (no toast loop, no work)
  - Before the loop: fire a single static toast `toast({ title: 'Sending N labels to the printer', duration: 0 })` (capture the toast id / dismiss handle from the toast API). Wording is exactly `Sending {N} labels to the printer` — honest about what we know (we're sending, not confirming print). The toast is purely a "system is alive" signal during the ~15s window for a 30-lot batch; it does not track per-iteration progress.
  - Loop body (serial): for each lotId in input order:
    1. Call `api<{ zpl: string }>('/labels/render', { method: 'POST', body: JSON.stringify({ lotId }) })` — wraps server render + flag-clear
    2. POST ZPL to `${helperUrl}/write` (Content-Type text/plain) — if non-200 or fetch throws, count as failure
    3. Catch errors per-iteration; tally `sent`/`failed` counts; do not abort the loop
  - After the loop: dismiss the static toast; the caller opens `BulkPrintVerifyDialog` with `{ sentCount, failedCount }` from the resolved promise. **Decision:** carry a `setVerifyDialog({ open: true, sent, failed })` state in `Inventory.tsx`; the hook returns `{ mutateAsync, ... }` and the caller awaits + manages the dialog state. Keeps the hook free of UI side effects beyond the static toast it owns.
  - `onSettled` invalidates `['lots-infinite']` (single invalidation, not per-lot)
  - Export type `BulkPrintResult = { sentCount: number; failedCount: number }`
